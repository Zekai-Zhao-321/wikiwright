# Roadmap

This page states what the current binary does, what was lost in the v2
delivery, and what remains unverified. [Architecture](architecture.md)
describes implementation; [the changelog](../CHANGELOG.md) lists the
removed v1 surfaces and their replacements.

## Status

WikiWright 0.1.0 is a Bun-only type-document engine. The kernel is
`@wikiwright/core`; the CLI has eight verbs: `check`, `gate`, `write`,
`rule`, `read`, `search`, `type`, and `version`. A bundle declares
`config/engine.json` at schema version 4 and YAML types, fragments and
vocabularies. Libraries are data imported by repository-relative path.
One judge handles the working tree, drafts over disk, the index over HEAD,
and a revision. The engine calls no model.

The local gate is `bun run check`: Biome, build, test-project typecheck and
whole suite. `scripts/hooks/pre-commit` runs it on commits in this clone;
`.github/workflows/check.yml` declares Linux and macOS jobs for pushes
and pull requests. The published `.pre-commit-hooks.yaml` and
[CLI one-liners](cli.md#gate) invoke the staged bundle gate and its
commit-message stage in a consuming repository.

The five synthetic corpora are `devwiki`, `fixtures/memory-synth`,
`fixtures/minimal-vault` and the orchard and allotment handbooks.
`devwiki` imports `libraries/kit-code`. The
[synthetic episode](../test/episode.test.ts) runs a repaired observation,
its rule and test set, a real commit-hook refusal, changed evidence
visible in `read` and `search`, and re-pinning twice with the same final
Git tree and generated bytes. The owner's real vault has not been run
through that episode in this repository.

## Limits of this delivery

### No starter command

`init` and the v1 starters left with the old command table. A new bundle
can copy [the documented starter](starter/README.md), edit its label and
type documents, and run `check --write`. The loss is a manual setup and
no completeness verdict until the first check. A `new` verb and generated
bundle skills wait until repeated work loses time assembling drafts or
finding a type despite the brief and examples.

### Remote evidence is unmeasured

`check` measures a pin against the repository enclosing the bundle.
A pin naming another Git URL is `pin-unmeasured` with reason
`remote-origin`; the engine does not contact it. When that source moves,
the page is not marked stale by this engine. A local clone named as an
origin, without network access by the engine, would close the gap.

A local pin holds a cited file path and line to the pinned tree, not the
meaning of the sentence that cites it. No `write` operation relocates
citations by content after a source moves. That requires a separate
content-based relocation operation and a reviewed re-pin.

A devwiki pin clean after its commit is normally `unchanged`, not
`current`: HEAD moved, but its covered paths did not. A tree copied with
fresh Git history lacks the commits the pins name; `check` then reports
`pin-unknown`. Carry the history or re-read and re-pin at the new history.

### A library is read from the bundle's own repository only

`libraries[].path` stays inside the enclosing Git repository, and its
bytes enter the law digest. To import a library from another repository,
a bundle must copy it; the copy has no live identity tie to its source.
Cross-repository distribution needs a way to name, obtain, and digest an
external library without violating the one-state law.

### No role bounds a session

`WIKIWRIGHT_ROLE`, the consumer/writer/maintainer verb guard and
`role-forbidden` left in step 6. The three roles survive in a bundle's
brief and [the skill documents](skills/), as guidance. The loss is
mechanical: a session given read access is not stopped by the engine from
running `write` or `check --write`. Host permissions and review bound it.

### A bundle runs no code of its own

The module loader, registration API, purity scan, determinism fixture and
code kit package left. A library is type, fragment and vocabulary data
with bounded CEL rules. A domain requirement outside the fixed grammar
and page interface is expressed as a CEL rule or needs a kernel change.
Arbitrary executable library hooks are outside this product's goal;
there is no deferred loader to enable.

### No exports, discovery, or host plugin

`export` and its selection planner, marker, copied-bundle read-only
refusal and `metadata.bundle.export` left. Sharing now shares a repository
whole; no engine-produced subset or independently installed copy is
available. Return when another consumer needs a subset or copy whose
identity can be checked against its source.

`--bundle` and `bundles list` left with installed-skill discovery.
A caller names a bundle by `--root`, or uses the working directory.
Several installed bundles can therefore cause targeting mistakes; a
future scan first needs verification against each host's actual layout.

The Claude Code plugin and its session-start and post-edit hooks left.
A host edit is judged at commit by `gate`, not when an editor lands it,
and a session is not told what bundles it can reach. Restore host
guardrails only after repeated bypasses or targeting mistakes, inside
the actual host with evidence of hook delivery. The engine does not
install Git hooks or compare installed ones with a published definition;
a missing hook leaves a repository unjudged.

The three skill documents live under `docs/skills/` and no verb installs
them. `generated/BRIEF.md` is a bundle's own current guidance. A host
distribution for the skills waits until repeated tasks lose time finding
the right type or verb despite the brief.

The repository also no longer carries the `CLAUDE.md` pointer to
`AGENTS.md`. A host that reads only that pointer will not receive these
operating rules unless they are supplied through that host's setup.

### Writes are complete per file, not transactional as a set

`write --from` proves the whole proposed batch, then stages complete
file replacements. Recorded bases, the proposed overlay and law use one
accepted capture, which is rechecked after temporary files are staged and
before the first rename. Known destination obstructions, unwritable destination
or moved-from parents and generated-directory links are refused in dry and real runs before any
replacement; `check --fix` also refuses a proposed repair that would leave a
new page error. It stages fixed pages and generated artifacts together before
either kind lands. A crash between renames can leave some old and some
new pages, or both names of a move before removal. `check --write` also
replaces each generated file atomically but can leave a mix across files.
The next generation converges artifacts; a partially landed write batch
requires review. A transaction across verbs is not implemented.

### Each run reads its corpus again

There is no persistent parse cache or daemon. `check`, `gate` and `read`
reuse a parsed page within one invocation, but a new invocation reads
again. `read` by name may parse every page to resolve it. This keeps Git
and disk as the only durable state and costs more as a corpus grows.
A caller that needs a warm parse can hold the pure core in its own
long-lived process; a cache inside this binary is not planned.

The static CEL bound counts comprehension iterations, not the linear
work of `in`, `join`, `contains`, or `matches` inside one iteration.
A rule admitted at the declared bounds can still take seconds on a large
page. No runtime rule budget exists in this delivery. Measure a real
latency breach before adding hard counters or another evaluation limit.

### Output and interface limits

An envelope over 1 MiB is `envelope-too-large`; `--out <file>` writes it
whole. There is no automatic spill, preview reserve or report directory.
Add those only if ordinary host output limits make `--out` burdensome.

The page interface is identified as `page-interface/1` in the law digest
but has no multi-version compatibility protocol. Independently updated
libraries that need different interfaces would trigger one. There is no
general assessment scale or configurable `cite_with` qualifier; use a
bundle rule when possible, and add a library only after a stable repeated
need.

### Other knowledge and agent gaps

A bundle cannot declare another bundle and the digests at which their
pages were reviewed together. `graph.json` records identity-level links
but no source line per occurrence; the CLI has no `references`,
`outline`, `resolve` or completion verb. `read` and `search` have no
applicability filter over conditions such as climate. A reader reports a
wrong or missing page to a maintainer by hand; no report type or proposal
verb sends it. Add these only against repeated concrete investigations.

There is no editor protocol, semantic retrieval tier, capture verb,
connector layer, rich-content checks, publication target, access
control, or historical page-as-of-time query. The engine never judges
prose truth. These are candidate product work, not implicit guarantees
of a green structural check.

### Platform and environment evidence

Bun is pinned by `.bun-version` and each `engines.bun`. The workflow
declares Linux and macOS, but this branch's host-runner execution has not
been independently verified here. `sh scripts/release-matrix.sh` is a
manual pre-release gate. On 2026-09-26 it passed all six arms on Darwin
arm64 under Bun 1.3.11: full gate, runtime pin, both package tarballs,
source/build verdict equality, clean build and corpus verdicts. That run
does not verify Windows or another operating system.

The suite runs several test files concurrently. Heavy machine load can
cause timeout failures; a passing rerun alone does not prove why an
earlier run failed. The packed-install test uses a temporary empty
package cache and needs network access to fetch dependencies. The CLI
reads Git child output through files because synchronous piped stdout
was observed cut short under load on Bun 1.3.11; the build-info writer
and test setup Git calls still use pipes, but neither chooses a page
to judge. `git-short-read` and `git-inconsistent-read` refuse detectable
short or contradictory answers.

A filesystem that preserves distinct NFC and NFD filenames can hold two
paths the engine normalizes to one key. The path law does not yet report
that collision. An authored `target_root` is constrained by the current
content-name index; a source root outside `content_roots` cannot be
targeted as a page reference. Both are stated until a representation
and test resolve them.

## Deferred mechanisms and triggers

| Mechanism | Trigger |
|---|---|
| `new`, `context`, generated bundle skills | repeated drafting or type-finding cost despite examples and the brief |
| Versioned page interface | independently updated libraries need different interface versions |
| Assessment library and citation qualifiers | the owner repeatedly uses a stable scale |
| Automatic spill and report directories | ordinary responses often exceed host limits |
| Exports and selections | a second consumer needs a subset or installed copy |
| Discovery scan and host hooks | repeated targeting mistakes or host write bypasses |
| More hook managers | a real installation settles on one; verify that route |
| Platform packages, wrapper and attestations | before an external release |
| Differential evaluator CI | profile upgrade or implementation-sensitive behavior |
| Hard performance counters | representative latency exceeds an agreed budget |
| Mutation testing and tooling changes | escaped defects or a concrete maintenance problem |
| Change replay, graph views and `doctor` | repeated investigation cannot use Git and current findings efficiently |

Never within this product's goal: executable bundle library hooks, an
automatic prover of arbitrary schema implication, a rule that law may
only tighten forever, or a compulsory multi-host installation framework.

## Delivery verification

The local v2 branch is ready for review when its devwiki pages have been
re-read and re-pinned, `check --root devwiki --all` has zero `pin-stale`,
`stale-source-cited` and `citation-unresolved` findings, the full gate
passes, and a whole-branch review accounts for the stated losses. The
manual release matrix is a separate pre-release gate. No push is part of
this delivery.

The owner may run the synthetic episode's sequence against the real vault
and its three libraries. That vault is outside this repository and was not
edited here.
