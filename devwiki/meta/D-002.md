# D-002 — One trust law: the digest over the package is the boundary

## Context

The engine once carried two ways to extend a bundle's law — a TypeScript
plugin file granted per machine, and the module system that registers
grammars, vocabularies, checks and lanes through one API — and the module
loader also read the consuming bundle's lockfile to refuse a module with no
lockfile pin. Two mechanisms for one job, and a lockfile parser that had
already misfired on Windows, were both package-manager hygiene or history
rather than wiki law: the trust grant already pinned every byte of the package,
`package.json` included, and `module-modified` fired the moment any of them
changed (`packages/cli/src/moduleload.ts`, 2026-09-05). Separately, every vault
load re-ran every declared module's determinism fixture before any verb could
read a page (`packages/cli/src/vaultio.ts`, 2026-09-05).

## Decision

One trust law. A module is admitted to the judge by a grant in this machine's
store, keyed by the vault's real path and the package name, pinned to the
sha256 over every file of the installed package except its own `node_modules`
(`packages/cli/src/moduleload.ts:110-146`, `:148-157`;
`packages/cli/src/trust.ts:10-16`, `:31-33`). The purity scan runs before the
trust gate, so a grant is never a way to admit impure code
(`packages/cli/src/moduleload.ts:390-393`). The determinism fixture runs once,
at the grant that pins the bytes, and a load under the granted digest is the
same proof (`packages/cli/src/verbs/trust.ts:140-163`;
`packages/cli/src/vaultio.ts:218-221`). No lockfile is read; the plugin tier,
its grants and the constitution compiler are gone.

## Consequences

- The repository alone no longer shows which module version a bundle
  resolved; the installed package and the machine-local grant do — a loss the
  commit states rather than hides.
- Editing any byte of a granted module, or moving the vault, revokes the grant;
  `trust list` reports `modified` against the same digest the loader reads
  (`packages/cli/src/verbs/trust.ts:70-88`).
- `git pull` can never write a grant, so a fresh clone of this repository runs
  `bun install` and `wikiwright trust grant module:@wikiwright/kit-code --root
  devwiki` before `check --root devwiki` judges anything.
