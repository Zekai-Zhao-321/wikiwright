# D-006 — A grant may cover a vault's path in every linked worktree of one clone

## Context

[[D-002]] keyed every grant by the vault's real path. An agent session that
opens a new linked worktree of the same clone meets its vault at a new real
path, so each session began refused as `module-untrusted`, and the refusal's
hint printed the grant command to run: the shortest way forward was an agent
approving code nobody had read (2026-09-11).

## Decision

D-002 stands: the digest over the package is the boundary, and the vault
grant keeps its key, its record and its one digest per module
(`packages/cli/src/trust.ts:12-19`, `:137-144`). A maintainer may instead
choose `--scope worktrees`, which approves the digest for the vault's path in
every linked worktree of its repository, keyed by the real path of the git
common directory and the vault's path inside its worktree, spelled as the
filesystem spells it (`:21-34`, `:203-219`); such a scope may hold several
digests (`:170-187`). A matching digest in either scope approves. The vault
grant is read first and needs no git; git is asked once per process, with the
variables a hook exports removed, and only when a worktree grant for the
module exists (`:221-242`, `:250-298`; `packages/cli/src/git.ts:431-474`); its answers are
read only from exactly three lines of output, so a path holding a newline has
no worktree identity rather than a shorter path's (`:459-469`). A
lookup that was needed and failed is its own refusal,
`module-scope-unresolved`, and no refusal names a command to run
(`packages/cli/src/moduleload.ts:223-267`, `:449-458`). Only a grant or a
revoke writes the store, as version 2, and a worktree record carries no
`vault` field, so an engine that predates scopes neither honours nor drops
it; a record of both shapes is refused (`packages/cli/src/trust.ts:71-128`).

## Consequences

- One maintainer grant covers this repository's `devwiki` in every linked
  worktree of one clone, existing and future: `wikiwright trust grant
  module:@wikiwright/kit-code --root devwiki --scope worktrees`.
- The keys are paths, and what paths cannot tell apart is stated: a
  replacement repository at the same common-directory path can inherit
  approval for the same module digest, moving the common directory ends the
  scope, a vault inside a submodule shares none, and a newline in the vault's
  path or in a linked worktree's common directory leaves no worktree scope
  (`docs/extending.md`,
  "Trust").
- Grants for paths that are gone stay in the store until revoked; an
  inventory and a prune are deferred (`docs/roadmap.md`, "A grant is keyed by
  where things are").
- Trust is a maintainer's decision: an agent must not grant trust to unblock
  its work (`AGENTS.md`, "Discipline").
