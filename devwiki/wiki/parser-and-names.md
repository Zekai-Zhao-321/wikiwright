# The parser and the names it binds

## Responsibilities

`packages/core/src/parse/index.ts` produces the one projection every checker
reads, `ParsedDoc`: frontmatter, headings, fences, wikilinks and the
normalized source (`:75-83`). `normalizeInput` (`:24-30`) strips a UTF-8 BOM
and folds CRLF to LF and reports both; `parseDoc` (`:190`) runs micromark and
mdast with the frontmatter extension alone — CommonMark plus YAML, the GFM
extensions deliberately not loaded, since no checker reads a table, a task
list, a footnote or an autolink and tokenizing them cost close to half of
every parse (`:4-11`, `:192-195`) — collects headings and fenced code,
excludes the frontmatter, fences, inline code and raw HTML by offset range
(`:201-239`), and scans wikilinks over the source outside those ranges
(`:98`, `:111-131`). `parseFrontmatterNode` (`:133`) parses the YAML
block with `yaml`'s `parseDocument` (`:137`) into the value, each key with its
page line (`:159-167`) and the issues `malformed-frontmatter`,
`duplicate-key` and `frontmatter-not-mapping` with a page line and a column
(`:31-38`, `:138-156`, `:172-178`).

`packages/core/src/identity/index.ts` is the one identity seam:
`normalizeIdentity` is NFD, then full Unicode case folding over the vendored
table, then NFC (`:19-26`); `foldCase` (`:9-17`) reads `CASE_FOLD` from the
generated `casefold-data.ts` (`:4`); `codeUnitCompare` (`:28-37`) is the only
comparator permitted for a sort that reaches an output.
`packages/core/src/names/index.ts` builds the name index — basename and alias
to path, with `viaAlias` and the declared type (`:33-55`) — and reports
`identity-collision` for a basename, alias or resolved title that another page
already owns (`:58-135`). `packages/core/src/paths/index.ts` is the kernel's
half of the path law: `pathRefusal` (`:66-85`) is the one reading of a
vault-relative path, `isVaultPath` (`:88`) and `isContentPath` (`:100`) branch
on it, and `PATH_REFUSALS` (`:35-46`) carries each refusal's message as data.
`packages/core/src/text/index.ts` holds the string metrics the claims module
and the near-name index both read: `boundedLevenshtein` (`:11`), `trigrams`
(`:37`), `trigramJaccard` (`:46`).

## Entry points

- `parseDoc` and `normalizeInput` (`packages/core/src/parse/index.ts:190`,
  `:24`), called through `parsedPages` once per page of a state
  (`packages/core/src/judge/index.ts:63-77`, `:440`) and by the Writer's
  frontmatter splices (`packages/core/src/writer/index.ts:392`).
- `normalizeIdentity`, `foldCase`, `codeUnitCompare`
  (`packages/core/src/identity/index.ts`).
- `buildNameIndex`, `checkVaultIdentity`, `basenameOf`
  (`packages/core/src/names/index.ts:33`, `:58`, `:137`); the judge builds the
  index once per call and runs the collision pass over every page
  (`packages/core/src/judge/index.ts:422`, `:510`).
- `pathRefusal`, `isVaultPath`, `isContentPath`, `PATH_REFUSALS`
  (`packages/core/src/paths/index.ts`), read by the page walk, the state
  constructors and the shell's containment check
  (`packages/cli/src/vaultio.ts:405`, `packages/cli/src/state.ts:91`,
  `packages/cli/src/paths.ts:100`).

## State

None. `casefold-data.ts` is a generated table from the vendored Unicode
`CaseFolding.txt`, regenerated by `bun tools/generate-casefold.ts`
(`tools/generate-casefold.ts:1-3`), and is the only data the module carries.

## Invariants

- Every identity comparison in the engine goes through `normalizeIdentity` —
  basenames, aliases, titles, the type and tag namespaces
  (`packages/core/src/identity/index.ts:19-23`); locale collation is banned in
  `packages/` (`:28-32`).
- Wikilinks are scanned over the source, never over mdast's decoded text, so a
  link survives reference-definition reshaping and an escaped `\[[` is not a
  link (`packages/core/src/parse/index.ts:105-110`, `:120`).
- The frontmatter is the first mdast child and nothing else is
  (`packages/core/src/parse/index.ts:243`); its value is a mapping or the page
  carries `frontmatter-not-mapping` (`:178-184`).
- A basename owns its identity before any alias: an alias that collides with
  a basename or another page's alias is a collision, and an alias never
  overrides a basename in the index (`packages/core/src/names/index.ts:41-46`,
  `:92-105`); a title equal to the page's own basename adds no identity and is
  not double-counted (`:115-118`).
- The path law refuses an empty path, a drive letter, a UNC path, an absolute
  path, a backslash, a control character, a trailing separator and an empty,
  `.` or `..` segment, in that order, and deliberately not a leading-dot
  segment, a space or a non-ASCII name
  (`packages/core/src/paths/index.ts:53-57`, `:66-85`); containment against
  a real directory is the shell's (`:12-15`).

## Failure modes

- A YAML error becomes `malformed-frontmatter` (or `duplicate-key` for
  `DUPLICATE_KEY`) with the page line and the parser's column, the excerpt
  dropped (`packages/core/src/parse/index.ts:144-162`); the judge stops the
  page at those findings, except for a duplicate key
  (`packages/core/src/lint/index.ts:209-217`).
- `identity-collision` names the kind of owner — basename, alias or title —
  and the owning path (`packages/core/src/names/index.ts:84-86`, `:97-99`,
  `:121-129`).
- A refused path throws in a reader (`packages/cli/src/vaultio.ts:48-51`) or
  is refused by name in an agent-facing verb
  (`packages/cli/src/paths.ts:79-97`).
