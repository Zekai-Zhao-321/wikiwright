# D-003 — The code kit is unpublished

## Context

`@wikiwright/kit-code` was shipped as a workspace package under
`packages/kit-code` (`packages/kit-code/package.json`, 2026-09-07). Every phrase in the
documentation, the starter's `package.json` and the loader's hints that
implied a registry version existed would have sent a consumer to a package
that is not there. The module loader resolves a package from the bundle's own
`node_modules` and nothing else (`packages/cli/src/moduleload.ts:91-101`),
which a workspace link, a `file:` dependency and a locally packed tarball all
produce (`:10-13`).

## Decision

The kit is stated as unpublished wherever a dependency spelling appears: the
workspace link inside this monorepo (`devwiki/package.json` depends on
`workspace:*`), or `file:<path>` to `packages/kit-code` in a checkout of this
repository anywhere else. The `init` envelope's install hint and the loader's
`module-unresolved` hint name a workspace link or a `file:<path>` and nothing
else (`packages/cli/src/moduleload.ts:244-252`). `engine.json`'s `version`
range stays as the loader's check against the installed package
(`:290-298`), not a registry lookup (`docs/extending.md`, 2026-09-07).

## Consequences

- The quickstart's install is `bun install` at the repository root, which
  links the kit into `devwiki/node_modules`; there is no `npm install` of a
  published name.
- The suite installs the kit into each temporary copy as a `file:` dependency
  on the shipped package (`packages/cli/test/fixtures/kit-code.ts:56-76`), so
  no test depends on a registry either.
- Publishing later is a new decision, not an amendment of this one.
