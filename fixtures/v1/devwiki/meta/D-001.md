# D-001 — Generated artifacts are tracked

## Context

`wikiwright check --write` rebuilds three files under `generated/` and `check`
without `--write` compares the tree against a fresh rebuild, reporting
`generated-drift` with `check --write` as the fixer
(`packages/core/src/passes/index.ts:187-193`). Whether a bundle commits those
files is the bundle's policy: an untracked artifact reads as missing at `check`,
and the staged gate rebuilds the artifacts from the index's own pages and
compares them with the index's bytes, judging a bundle that tracks none of
them on none of them (`packages/cli/src/staged.ts:26-34`, 2026-09-05). The brief joined the artifacts later: it is rendered per install
from the verb registry and the loaded constitution, and an engine change that
moves a verb or a skill fragment moves it (`packages/cli/src/artifacts.ts`,
2026-09-07).

## Decision

This bundle tracks `generated/graph.json`, `generated/manifest.json`,
`generated/tag-catalog.md` and `generated/BRIEF.md`. A byte-reproducible
artifact is committed so that `generated-drift` at the gate is a real check on
a reviewer's commit, and so that `brief-stale` names an engine change rather
than reading as machine-local noise. `generated/freshness.json` is not tracked:
it derives from origin state outside the vault snapshot
(`packages/cli/src/freshness.ts:435`).

## Consequences

- Every commit that changes a page runs `wikiwright check --write --root devwiki`
  first — the brief lands with the artifacts — or the gate refuses it with the
  artifact named.
- The engine's own suite removes a copy's `generated/` and rebuilds it from
  nothing, then compares every tracked byte
  (`packages/cli/test/generated-tracked.test.ts`), so a tracked file the
  generators no longer write is a missing file, not a stale copy that happens
  to match.
- A partial staging passes only when the staged artifacts describe exactly the
  staged pages.
