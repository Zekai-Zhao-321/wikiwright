# D-007 — Installing is consent; every load proves the module

## Context

[[D-002]] admitted a module by a grant in this machine's store, pinned to the
digest over the installed package, and ran the determinism fixture once, at
the grant; [[D-006]] let a grant cover a vault's path in every linked worktree
of one clone. A kit that arrived by a workspace link, a `file:` dependency, a
tarball or a copy in the bundle's own tree had already been accepted when it
was installed, and the grant asked a second time on every machine and every
clone, for a bundle whose law names the same bytes everywhere. A bundle copied
elsewhere with its kit could not be read at all until someone granted it
there (2026-09-24).

## Decision

Installing is the consent. The `trust` verb, its store and its scopes are
removed, with `module-untrusted`, `module-modified`, `module-scope-unresolved`
and `trust-store-malformed`. The two proofs the grant ran move into every
load: after the purity scan and the entry and fixture checks, and after the
entry is imported, the loader runs the module's determinism fixture and
refuses with the fixture's own code
(`packages/cli/src/moduleload.ts:547-561`). Both proofs are kept for the
process by the digest of the module's bytes and the scan's version, never
between processes (`:313-340`, `:702-707`). A declaration may name a
bundle-relative `path`, read by one resolver with no fallback to
`node_modules` (`:118-199`). The purity scan refuses an import of any form
and computed access to a banned global, and its version rose to 2
(`packages/core/src/modules/purity.ts:22-28`, `:73-94`).

## Consequences

- Nothing on this machine asks before a module runs: a `git pull` that
  changes a carried kit, or the modules a bundle declares, changes the code
  the next verb over it runs. Review of that change is the guard, as for any
  dependency, and `docs/roadmap.md` states the loss ("A module runs because it
  is installed").
- The fixture's cost returns to every process that loads a module, which
  D-002 had moved to the grant: the code kit's fixture took a median of
  32.7 ms in a fresh process on one machine (`docs/roadmap.md`, "A module's
  proofs are taken once per process"). A cache kept between runs is deferred.
- The scan narrows and does not sandbox; it is not the argument for running
  a module (`docs/extending.md`, "The purity scan", "Loading a module").
- `check --root devwiki` needs `bun install` and nothing else.
